# Крестики-нолики онлайн

Игра 1 на 1 в реальном времени: Vue 3 на клиенте, Node.js + Fastify на сервере.
Без регистрации — комната создаётся по кнопке, второй игрок заходит по коду или ссылке.

```
┌────────────┐   HTTP (create/join)   ┌──────────────┐
│  Vue 3 SPA │ ─────────────────────► │ Fastify API  │
│  Pinia     │ ◄───────────────────── │ RoomRegistry │
│            │   WebSocket (state)    │  (in-memory) │
└────────────┘                        └──────────────┘
```

## Что умеет

- **Комната на двоих** — 6-символьный код без похожих символов (`0/O`, `1/I/L`), ссылка-инвайт, вход по коду.
- **Сервер — арбитр.** Клиент не решает, чей ход и кто победил; любой ход проверяется на сервере.
- **Защита от гонок** — у состояния есть `version`, устаревший или повторный ход отклоняется (`STALE_STATE`).
- **Переподключение** — обрыв связи даёт 30 секунд; вернувшийся игрок попадает в ту же партию, иначе партия помечается `abandoned` с победой оставшегося. Если не осталось никого, победа не присуждается.
- **Живость соединений** — сервер сам пингует сокеты и закрывает «мёртвые», поэтому зависшие соединения не блокируют `abandoned`.
- **Рематч** — оба голосуют, доска очищается, метки меняются (`X ↔ O`), чтобы первым ходил по очереди другой игрок.
- **Валидация и лимиты** — JSON-схемы Fastify, единый формат ошибок, лимит размера WS-сообщения, rate limit на HTTP и WS-сообщения, лимит сокетов с одного IP и комнат в памяти, проверка `Origin`.
- **UI** — тёмная адаптивная тема, подсветка выигрышной линии, баннеры «нет связи», клавиатурная навигация, `aria-live` для статуса, `prefers-reduced-motion`.

## Быстрый старт

Требуется Node.js ≥ 22.12.

```bash
npm install
npm run dev
```

- клиент: <http://localhost:5173>
- сервер: <http://localhost:3000> (Vite проксирует `/api` и `/ws`)

Проверка: откройте две вкладки (или окно в приватном режиме) — в первой нажмите
«Создать игру», во второй откройте ссылку из комнаты.

### Прод-режим (один origin)

```bash
npm run build
npm start
# http://localhost:3000 — Fastify отдаёт собранный клиент и API
```

## Конфигурация

Сервер читает переменные окружения (и `apps/server/.env`, если файл есть — см. `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт HTTP/WS |
| `HOST` | `0.0.0.0` | интерфейс |
| `CLIENT_ORIGIN` | пусто | белый список origin через запятую для CORS и проверки `Origin` у WS; пусто = CORS выключен, Origin у WS не проверяется (только для локальной разработки) |
| `TRUST_PROXY` | `false` | доверять `X-Forwarded-*`; включайте только за reverse-proxy, иначе rate limit будет считать всех одним IP |
| `MAX_ROOMS` | `10000` | максимум комнат в памяти; при переполнении создание отвечает `503 ROOM_LIMIT` |
| `MAX_SOCKETS_PER_IP` | `8` | максимум одновременных WS-соединений с одного IP |
| `ROOM_TTL_MS` | `600000` | через сколько удаляется комната, в которой не осталось подключённых игроков |
| `STATIC_DIR` | `apps/client/dist` | каталог собранного клиента |

Клиент: `VITE_API_URL` (по умолчанию пусто = тот же origin) и `VITE_WS_URL` (по умолчанию выводится из API/текущего origin — нужно, только если сокет живёт на отдельном домене). Пример — `apps/client/.env.example`. Сессия игрока хранится в `sessionStorage`, поэтому у каждой вкладки своя партия; имя — в `localStorage`.

## HTTP API

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| `POST` | `/api/games` | `{ "name": "Аня" }` | `201 { gameId, code, playerId, token, mark: "X" }` |
| `POST` | `/api/games/:code/join` | `{ "name": "Боб" }` | `201 { gameId, code, playerId, token, mark: "O" }` |
| `GET` | `/api/games/:code` | — | `200 { game: PublicGame }` |
| `GET` | `/health` | — | `200 { ok: true }` |

Ошибки: `{ code, message }`, где `code` — машинный (`ROOM_FULL`, `ROOM_LIMIT`, `NOT_FOUND`, `RATE_LIMITED`, …).
Ошибки валидации Fastify и rate limit также приводятся к этому формату.
`token` — секрет игрока для переподключения; в `PublicGame` он не попадает.

## WebSocket

Подключение: `ws(s)://<host>/ws?token=<playerToken>`.
Невалидный токен → закрытие с кодом `1008`. Новый сокет того же игрока вытесняет старый (`4001`).

Клиент → сервер:

```json
{ "type": "move", "gameId": "…", "index": 4, "version": 3 }
{ "type": "rematch" }
{ "type": "leave" }
{ "type": "ping" }
```

Сервер → клиент:

```json
{ "type": "state", "game": { "...": "PublicGame" }, "you": "X" }
{ "type": "error", "code": "NOT_YOUR_TURN", "message": "Сейчас ход соперника" }
{ "type": "pong" }
```

Решения, которые стоит знать:

- **Полный снапшот вместо диффов.** На 9 клетках экономить нечего, зато невозможен рассинхрон.
- **`version` обязателен в ходе.** Двойной клик или два таба не «перескочат» ход.
- **`you` приходит в каждом `state`.** После рематча метки меняются, и клиент узнаёт об этом из снапшота, а не из локальной сессии.
- **Состояние `abandoned`** приходит и при явном выходе, и по истечении grace-периода.
- **Лимиты** — 10 ходов/с, 30 любых сообщений/с на сокет, 8 сокетов с одного IP, 4 КБ на сообщение.
- **Heartbeat** — сервер пингует сокеты раз в 30 секунд и закрывает не отвечающие.

## Правила и граничные случаи

- Поле 3×3, побеждают 8 линий; `X` всегда ходит первым; хост получает `X`.
- Партия стартует, когда второй игрок вошёл в комнату; если он так и не открыл сокет, через grace-период партия отменяется.
- Нельзя: ходить не в свой ход, в занятую клетку, после финала, с чужим `version`, третьим игроком, с индексом вне `0..8`.
- Третий игрок получает `ROOM_FULL`; вход в несуществующую комнату — `NOT_FOUND`.
- Обрыв связи: 30 с на возврат, затем `abandoned` (победитель — оставшийся в сети игрок).
- Оба ушли — комната отменяется без победителя.
- Комната удаляется через `ROOM_TTL_MS` (по умолчанию 10 минут) после того, как в ней не осталось подключённых игроков (sweep раз в минуту).
- Лимиты: 30 созданий/входов в минуту с IP, 120 чтений комнаты в минуту с IP, 10 ходов/с и 30 сообщений/с на сокет, 8 сокетов с IP, не больше `MAX_ROOMS` комнат.
- Имя: 1–20 символов, пробелы схлопываются, управляющие символы вырезаются.
- Доска блокируется, пока ход соперника или нет соединения.

## Тесты

```bash
npm test
```

- `packages/shared` — 24 теста: все выигрышные линии, ничья, очередность, занятые клетки, версии, рематч со сменой меток, санитайзинг имён, отсутствие утечки токенов.
- `apps/server` — 20 интеграционных сценариев на реальном HTTP + WebSocket: полная партия, `ROOM_FULL`, `ROOM_LIMIT`, `NOT_YOUR_TURN`/`STALE_STATE`/`CELL_TAKEN`, отмена по grace-таймеру, уход обоих игроков, гость без сокета, реконнект, невалидный токен, неизвестное сообщение, `Origin`, лимиты HTTP/WS, единый формат ошибок, удаление комнат sweep-ом.
- `apps/client` — 23 теста: тексты статусов, компонент доски (9 клеток, клики, блокировки, `aria-label`, подсветка линии) и Pinia-стор (создание игры, снапшоты, защита от двойного клика, смена меток после рематча, восстановление сессии).

## Docker

```bash
docker compose up --build
# http://localhost:3000
```

`Dockerfile` — multi-stage: сборка клиента → рантайм с прод-зависимостями. Контейнер работает от пользователя `node`, у сервиса есть `HEALTHCHECK` на `/health`.
`CLIENT_ORIGIN` в `docker-compose.yml` уже включает `localhost` и `127.0.0.1`; для своего домена добавьте его в список. В проде без `CLIENT_ORIGIN` сервер пишет предупреждение: CORS выключен, а Origin у WebSocket не проверяется.

## Ограничения и что дальше

Осознанно **вне MVP**:

- комнаты и токены живут **в памяти процесса** — рестарт сервера стирает партии;
- нет аккаунтов, БД, истории партий, рейтинга, чата, зрителей и таймера на ход;
- горизонтальное масштабирование требует sticky sessions и общего хранилища (Redis) — `RoomRegistry` специально повторяет интерфейс, который легко заменить адаптером;
- нет ESLint/Prettier и e2e на Playwright — при желании добавляются без изменения архитектуры.
